# VV64-A0 Architecture and FPGA Subset

## Status

`VV64-A0` is the native 64-bit continuation of VICTORY-V. It inherits the capability, Secret Tag, `VTRY`, and `VIC` rules from `VV32-A0`.

The repository contains a synthesizable in-order Tang 138K subset. It is not a complete Linux CPU and has not yet been placed, routed, or observed on a board.

| Area | Current subset | Later profile |
|---|---|---|
| 64-bit integer state and PC | yes | yes |
| 32-bit-generation Capability Directory | yes | yes |
| complete register/directory rollback | yes | yes |
| inline and prepared `VTRY` entry | yes | yes |
| write-set merge and commit preflight | yes | yes |
| fixed architectural release cycle | yes | yes |
| VRTU exact range protection | yes | yes |
| no-MMU Linux path | prepared | port required |
| privilege modes | no | required |
| tagged context memory | no | required |
| atomics/fences | no | required |
| DDR3/caches | no | required |
| paged `V39` MMU | no | optional |

## P0 and E0

P0 and E0 execute the same ISA. Their difference is admitted capacity.

| Profile | Capability Directory | Store granules | Derived capabilities | VRTU entries |
|---|---:|---:|---:|---:|
| P0 | 32 | 8 | 8 | 4 |
| E0 | 8 | 2 | 2 | 2 |

Both profiles support up to 31 distinct register writes because the A0 RTL keeps a complete architectural checkpoint. A contract that does not fit E0 is rejected before entry and can be sent to P0 instead.

## Register and capability state

Each register carries a 64-bit value, a Capability Directory reference plus 32-bit generation, a Secret Tag, and a contract-token generation tag. Integer-producing instructions clear authority and token metadata.

The Directory is part of the Victory Region checkpoint. Entry saves every live slot, its generation, and the allocator position. Abort restores that state; commit keeps it. `CBOUNDS` and `CPERM` may derive capabilities inside a prepared contract while the admitted allocation quota remains. `CROOT` is not allowed inside a Region.

A generation is never silently wrapped to a live value. Exhaustion raises `CAPABILITY_GENERATION_WRAP` instead of reviving a stale reference.

## VTRY forms and commit

`VTRY fail, stores, budget` is the direct form. It remains useful for small fixed jobs.

The prepared form starts with `VPREP`, which checks the requested stores, instruction budget, register writes, derived capabilities, arena, and optional release cycle against the selected profile. `VTRY cToken, fail` consumes the admitted token and enters the same checkpoint as the direct form. `VCANCEL` invalidates a token that will not be used. Opcode `0x3d` is `VTRYC` internally, but it is not a separate architectural entry instruction.

Stores to the same aligned 8-byte granule merge. `VIC` enters `ST_PREFLIGHT` and probes every buffered entry through VRTU without issuing a write. Only a fully validated set enters `ST_COMMIT`. Device ranges fail with `REGION_DEVICE`. A fault after publication begins is `COMMIT_PROTOCOL` and halts the core; it is not reported as a successful rollback.

A fixed-release contract holds success or failure until the admitted cycle. Secret contracts require fixed release. This constrains the architectural completion signal, not physical side channels.

## VRTU

Both profiled cores put `vv_vrtu` between the core buses and the SoC.

```text
virtual range [vbase, vtop)
    -> complete-access and permission check
    -> pbase + offset
```

The core supplies the logical access size and privilege input. VRTU rejects Region access to `DEVICE` descriptors. Descriptor and guard generations are 32 bits. Configuration rejects empty ranges, physical overflow, overlap, `DEVICE+X`, permission widening, and generation wrap before the new mapping becomes visible.

VRTU has no software refill and no page walker. A generation-checked last-range guard may bypass the small descriptor bank only while the same entry still proves the complete access.

See [`VRTU.md`](VRTU.md).

## Linux profiles

`VV64-L0-flat` remains first:

```text
CONFIG_MMU=n
FDPIC or FLAT userspace
VRTU range protection
```

`VV64-L0-paged` comes later. It should be added only after the no-MMU port shows a specific need for sparse address spaces, copy-on-write, or demand paging.

## Tang 138K image

```text
VV32-A0 control
VV64-A0/P0 + VRTU-P0
VV64-A0/E0 + VRTU-E0
private RAM, UART, mailbox, timer, IPI
```

The boot ROM exercises direct `VTRY`, prepared `VTRY`, rollback, and device rejection before it prints `VTRY ready`. The old Euclid RTL is an isolated experiment under `experiments/euclid/` and is not part of this image.
