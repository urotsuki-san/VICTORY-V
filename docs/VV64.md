# VV64-A0 Draft Architecture

## Status

This is the native 64-bit continuation of `VV32-A0`. It is a design draft. There is no 64-bit assembler, executable model, RTL core, compiler target, or Linux port in the repository yet.

The draft exists to settle the machine rules before those implementations start.

## Base machine

| Property | `VV64-A0` draft |
|---|---|
| Instruction width | fixed 32 bits |
| Integer width | 64 bits |
| Registers | 32 architectural registers |
| Program counter | 64 bits, four-byte aligned |
| Byte order | little-endian |
| Architectural address width | 64 bits |
| First FPGA physical width | implementation-defined, expected 32–40 bits |
| Privilege | Monitor, Supervisor, User |
| Translation | optional |
| First core | single-issue, in order, non-speculative |
| Nested Victory Regions | prohibited in A0 |
| SMP, FPU, vectors | outside A0 |

An implementation that supports fewer than 64 physical address bits must trap when unsupported high bits are used. It must not silently alias them.

`r0` remains zero and untagged. `rN`, `cN`, and `sN` remain aliases for the same register state.

## Inherited behavior

The existing arithmetic, control, capability, secret-flow, and Victory instructions keep their meaning. Natural integer operations use XLEN. Byte, halfword, and word memory operations keep their stated access size.

The extension pages add:

- 32-bit word arithmetic with defined sign extension;
- 64-bit load and store;
- division and remainder;
- tagged capability load and store;
- atomics and fences;
- sealed control flow;
- privilege and translation operations.

Opcode continuity does not make a `VV32-A0` binary automatically executable on `VV64-A0`. Compatibility mode is deferred until traps, ABI, and context layout are stable.

## Tagged register state

Each register has:

```text
value[63:0]
capability tag
Capability Directory reference + generation
secret tag
```

The directory entry contains full bounds, permissions, domain, object type, generation, and sealing state. Ordinary memory cannot edit the directory.

Integer-producing instructions clear the destination capability tag. Copying a capability preserves its directory reference and generation. Bounds and permissions may only shrink.

## Stored capabilities

`VV64-A0` adds tagged context memory:

```text
CLDC    load a cursor and its authority metadata
CSTC    store a cursor and its authority metadata
```

These instructions work only on memory marked tag-capable. An ordinary integer store clears any capability tag at its destination. DMA does not create or copy capability tags unless it is attached through a separately trusted tag-aware path.

This makes task switching possible without serializing authority into forgeable bytes.

## Privilege and domains

### Monitor

Monitor mode owns reset, initial roots, the Capability Directory, domain creation, and optional translation roots. It delegates authority and then executes `VLOCK`.

`VLOCK` closes root bootstrap and directory-bootstrap paths until reset. It does not block ordinary derivation, context switching, or permitted page-table maintenance.

### Supervisor

Supervisor mode is the Linux kernel level. It manages processes, interrupts, devices, and optional page tables within authority delegated by Monitor. Supervisor privilege alone cannot manufacture a capability or read Monitor-private state.

### User

User mode runs inside a domain with capabilities for code, data, stack, and kernel entry. Guessing a numeric physical address does not grant authority to it.

## Physical and paged modes

Physical mode is mandatory and supports bare metal, RTOS work, and `VV64-L0/flat` Linux.

The optional `V39` profile adds 39-bit virtual addresses, 4 KiB base pages, three page-table levels, larger leaves, TLBs, and page faults. The page-table format is not yet frozen.

The fixed rule is:

```text
effective permission = capability ∩ domain ∩ page ∩ privilege
```

Translation cannot add authority.

## Sealed control flow

`VV64-A0` turns the reserved execute permission into an enforceable call discipline.

- Indirect entry requires an executable capability.
- Cross-domain entry uses a sealed call gate.
- `CALLC` creates a protected return token.
- `RETC` consumes that token.
- An ordinary integer cannot be substituted for a return token.

The first implementation may keep return tokens in protected on-chip memory.

## Secret flow

The source architecture's secret bit remains part of the base contract.

Secret data may be processed, but it cannot select a branch, call target, return target, address, page-table update, or public store. Declassification still requires explicit `D` authority.

A tagged context containing secret state must be stored in secret, tag-capable memory. Abort paths scrub affected secret registers before control passes to a less trusted domain.

This mechanism does not claim to stop power, electromagnetic, or every timing side channel.

## Victory Regions

The inherited form remains:

```asm
vtry   failed, stores, budget
...
vic
```

It defers interrupts for a bounded execution and commit window.

The 64-bit draft adds an abort-on-interrupt form:

```asm
vtrya  failed, stores, budget
```

When an enabled interrupt arrives, `VTRYA` discards staged stores, scrubs secret registers, records the interruption in `VERROR`, reaches the failure edge, and then takes the interrupt. Linux code should normally prefer this form.

For both forms:

- staged stores are visible to the region through forwarding but not to other agents;
- `VIC` commits in program order;
- MMIO, DMA submission, and page-table publication are prohibited inside A0 regions;
- atomics are prohibited inside A0 regions;
- staged cache lines cannot be written back before commit.

## Atomics and ordering

Linux requires atomic read/modify/write and a defined memory model. `XATOM` will include capability-checked reservation, compare/exchange, a small set of fetch operations, acquire/release ordering, full fences, and instruction-stream synchronization.

Every atomic names valid authority. Secret or out-of-bounds addresses fail before the operation is issued.

The first hardware target is single-core, but DMA and devices still make ordering observable. The memory model must be written before SMP work begins.

## Caches and speculation

Caches are optional. When present, data, capability tags, secret policy, and directory generations remain coherent. Eviction must not turn hidden metadata into ordinary bytes.

The first core does not perform speculative loads, stores, indirect calls, or page walks. Later implementations may speculate internally only if aborting leaves no visible authority or shared-state effect. That is not an A0 objective.

## First RTL configuration

```text
one VV64-A0 core
single issue, in order
no FPU, vectors, SMP, or dynamic branch predictor
Capability Directory in protected BSRAM
on-chip RAM and UART first
interrupts and tagged context next
DDR3 after model/RTL comparison
```

Physical mode comes before `V39`.

## Open items

- extension-page sub-opcodes;
- directory index and generation widths;
- tagged-memory granularity;
- atomic memory model;
- trap and signal-frame layouts;
- `V39` page-table bits and invalidation rules;
- flat and paged ABI details;
- debugger access to tagged state;
- Victory Region behavior across debug halt and reset.
