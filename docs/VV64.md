# VV64-A0 Architecture and FPGA Subset

## Status

`VV64-A0` is the native 64-bit continuation of the VICTORY-V family. It inherits the rules established by `VV32-A0`; it does not replace the 32-bit architecture.

The architecture contract is still a draft. The repository contains a synthesizable FPGA subset, P0/E0 wrappers, and self-checking RTL tests. That subset is smaller than the eventual Linux-capable machine.

| Area | FPGA subset | Full VV64-A0 contract |
|---|---|---|
| 64-bit integer state and PC | yes | yes |
| inherited VV32 primary opcodes | yes | yes |
| 64-bit capability load/store | yes | yes |
| protected Capability Directory | yes | yes |
| Secret Tags | yes | yes |
| Victory Regions and `VLOCK` | yes | yes |
| basic CSRs, traps, interrupt input | yes | yes |
| P0/E0 implementation wrappers | yes | yes |
| tagged context spill/fill | no | required |
| Monitor, Supervisor, User | no | required |
| atomics and fences | no | required |
| sealed calls and returns | no | required |
| `VTRYA` | no | required |
| caches, DDR3, page translation | no | optional/later |

Unsupported extension-page operations trap as illegal instructions.

## Base machine

| Property | `VV64-A0` |
|---|---|
| Instruction width | fixed 32 bits |
| Integer width | 64 bits |
| Registers | 32 architectural registers |
| Program counter | 64 bits, four-byte aligned |
| Byte order | little-endian |
| Architectural address width | 64 bits |
| First FPGA physical width | 17 bits in the bring-up image |
| Privilege | Monitor, Supervisor, User in the full profile |
| Translation | optional and absent from the first image |
| First core | single-issue, in order, non-speculative |
| Nested Victory Regions | prohibited in A0 |
| FPU and vectors | outside A0 |

An implementation with fewer than 64 physical address bits must trap when unsupported high bits are used. It must not silently alias them.

`r0` remains zero and untagged. `rN`, `cN`, and `sN` are aliases for the same register state.

## P0 and E0

P0 and E0 are implementation profiles of `VV64-A0`.

```text
same ISA
same ABI
same traps
same context format
same atomics and memory ordering
```

The first wrappers only change two budgets:

| Profile | Capability Directory | Victory Region stores |
|---|---:|---:|
| P0 | 32 entries | 8 |
| E0 | 8 entries | 2 |

This gives the Tang 138K image a real 1P1E boundary without inventing a second 64-bit ISA. It is not yet a performance result. Both profiles still use the same execution engine and private 64 KiB bring-up RAM.

Later P0 may gain larger caches and faster arithmetic. E0 may use smaller caches and iterative arithmetic. Software-visible behaviour must remain identical.

## Encoding continuity

The primary opcode positions from `VV32-A0` are unchanged. The FPGA core implements the inherited base operations directly and uses `XMEM` for doubleword access:

```text
XMEM function 0: CLDD
XMEM function 1: CSTD
```

The remaining extension pages are reserved by purpose:

| Opcode | Page | Purpose |
|---:|---|---|
| `0x36` | `XALU` | division, remainder, word operations, constant lanes |
| `0x37` | `XMEM` | 64-bit and tagged context memory operations |
| `0x38` | `XATOM` | reservation, compare/exchange, atomic RMW, fences |
| `0x39` | `XCALL` | sealed entry, protected call and return |
| `0x3a` | `XSYS` | privilege, context, interrupt, and domain operations |
| `0x3b` | `XVM` | optional page translation and TLB maintenance |
| `0x3c`–`0x3f` | reserved | left unused in A0 |

Only the two listed `XMEM` functions are assigned by the current RTL. Other sub-opcode layouts are not frozen.

## Tagged register state

Each register has:

```text
value[63:0]
capability tag
Capability Directory index + generation
secret tag
```

A directory entry contains 64-bit base and top bounds, permissions, validity, and an 8-bit generation. Reusing an entry changes its generation. An older register reference then fails instead of acquiring authority over the replacement entry.

Integer-producing instructions clear the destination capability tag. Copying a capability preserves its directory reference. `CBOUNDS` and `CPERM` allocate a narrowed entry. `CINC` changes only the cursor and checks the existing bounds.

Directory size and generation width are implementation choices until the tagged context ABI is frozen.

## Stored capabilities

The full architecture adds tagged context memory:

```text
CLDC    load a cursor and its authority metadata
CSTC    store a cursor and its authority metadata
```

These operations are not in the current FPGA subset. Ordinary integer stores carry no capability tag. Linux context switching waits for this path.

## Privilege and domains

### Monitor

Monitor owns reset, initial roots, the Capability Directory, domain creation, and optional translation roots. It delegates authority and then executes `VLOCK`.

### Supervisor

Supervisor is the Linux kernel level. It manages processes, interrupts, devices, and optional page tables within authority delegated by Monitor.

### User

User runs inside a domain with capabilities for code, data, stack, and kernel entry.

The current FPGA subset does not distinguish these modes yet.

## Physical and paged modes

Physical mode is mandatory and is the only mode implemented by the first RTL image.

The optional `V39` profile adds 39-bit virtual addresses, 4 KiB base pages, three page-table levels, larger leaves, TLBs, and page faults. Its page-table format is not frozen.

The fixed rule is:

```text
effective permission = capability ∩ domain ∩ page ∩ privilege
```

Translation may deny an access. It may not add authority.

## Sealed control flow

The full architecture uses executable capabilities, sealed call gates, protected return tokens, `CALLC`, and `RETC`. The first FPGA subset leaves `XCALL` unimplemented.

## Secret flow

Secret data may be processed, but it cannot select a branch, indirect target, address, or public store. Declassification requires explicit `D` authority.

The current core scrubs secret registers when a Victory Region aborts. It does not claim to stop power, electromagnetic, or every timing side channel.

## Victory Regions

The inherited form remains:

```asm
vtry   failed, stores, budget
...
vic
```

Stores are forwarded to the executing core but remain outside memory until `VIC`. A fault or failed `VCHK` discards them, records `VERROR`, scrubs secret registers, and reaches the failure edge.

The full VV64 contract also defines `VTRYA`, which aborts on an enabled interrupt. `VTRYA` is not in the first FPGA subset.

MMIO and atomics remain prohibited inside A0 regions.

## Tang 138K configuration

```text
VV32-A0 control core
VV64-A0/P0
VV64-A0/E0
three private on-chip RAMs
shared UART, mailboxes, timebase, timer compare, and IPI bits
fixed ROM
no DDR3, caches, MMU, FPU, vectors, or shared SMP memory
```

The image proves boot order and coexistence. It does not yet provide Linux scheduling, shared memory, or cache coherence.
