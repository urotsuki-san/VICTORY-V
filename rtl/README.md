# VICTORY-V RTL

The RTL directory contains two cores and one deliberately small bring-up SoC.

## Cores

### `vv32_core.sv`

The existing `VV32-A0` core is a single-issue, in-order, multi-cycle design. It keeps capability metadata and Secret Tags beside the register file and uses a bounded store buffer for Victory Regions.

### `vv64_core.sv`

The new VV64 core is an FPGA bring-up subset of `VV64-A0`. It keeps the VV32 primary opcode positions and widens registers, the PC, CSRs, and the data port to 64 bits.

Implemented in this subset:

- base integer and control instructions;
- byte, halfword, word, and doubleword capability memory access;
- a protected Capability Directory with generation-checked references;
- Secret Tags and the base control/address/store checks;
- `VLOCK`;
- bounded Victory Regions with forwarding, commit, rollback, and secret scrub;
- basic CSRs, traps, interrupts, and `WFI`.

Not implemented yet:

- Monitor/Supervisor/User privilege;
- tagged capability spill/fill;
- atomics and fences;
- sealed calls and protected returns;
- `VTRYA`;
- caches, DDR3, or page translation.

The missing operations trap as illegal instructions rather than pretending to work.

## Tang 138K bring-up SoC

`rtl/soc/vv_dual_bringup.sv` instantiates both cores. Each has its own on-chip RAM. The cores share a UART and a small MMIO page for status mailboxes and LEDs. VV32 starts first; VV64 is released after VV32 reports or after a timeout.

The fixed ROM is generated by `tools/gen_fpga_bringup.py` and prints:

```text
VV32-A0 ready
VV64-A0 ready
```

Run all RTL simulations with:

```bash
make rtl-test
```

Run only one stage with:

```bash
make rtl-test-vv32
make rtl-test-vv64
make rtl-test-dual
```

Board projects and pin constraints are under `fpga/tang-138k/`.

Still missing: reviewed Gowin synthesis warnings, timing results, bitstream hashes, UART transcripts from real hardware, CDC analysis for future clock domains, and DDR3 integration.
